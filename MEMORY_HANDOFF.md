## 3. Key Decisions
- **Draft Scores' release scope is season-wide, not per-league, by design** — accepted tradeoff so any commissioner can release live without waiting on a site admin, even though `draft_couple_releases` isn't scoped to the releasing commissioner's own league.
- **A couple can be draft-released or live-revealed, never both** — the two mechanisms are mutually exclusive per couple but independent per night (some couples released, some live-revealed, some still drafting, all at once is valid).
- **Schedule and Scores must agree on episode status.** Scores' rule ("a published episode always reads Published, regardless of an in-progress correction draft") is the one to match — Schedule isn't a draft-workflow page, so it shouldn't expose Enter-Results-internal state.
- **RPC-exists verification trick** (used repeatedly tonight for both schema migrations): call it via the service-role key — `"permission denied for function X"` means it exists (service_role isn't `authenticated`); `"Could not find the function"` means it's genuinely missing.
- **Schema migrations get committed locally but held from pushing** until the user confirms the `.sql` file has been run in the Supabase Dashboard and it's been verified against the live DB — both of tonight's migrations (`apply-per-couple-draft-release.sql`, `apply-grand-finale-late-edit-close.sql`) followed this sequencing.
