# Mirrorball Madness

Fantasy sports app for Dancing with the Stars. Next.js 15 (App Router), TypeScript, Tailwind CSS v4, Shadcn UI (base-nova style, built on Base UI), Supabase (Auth + Realtime + Postgres).

## Commands

- `npm run dev` — dev server
- `npm run build` — production build (type-checks as part of the build)
- `npm run lint` — ESLint
- `npm test` — Vitest, runs logic tests and isolated PostgreSQL publication/rollback tests under `src/lib/` (PGlite; no live database needed)
- Regenerate types after any schema change:
  ```
  npx supabase gen types typescript --project-id wssbwgtsejamlbvfofvu --schema public > src/lib/supabase/types.ts
  ```
  Needs `SUPABASE_ACCESS_TOKEN` (personal access token from supabase.com/dashboard/account/tokens) — this container has no Docker for local introspection.

`supabase/schema.sql` is the source of truth for the DB schema. It's applied directly via `psql` (no migration files/CLI linking).

## Rules

- **Write clean code.** No dead code, no speculative abstractions, no comments explaining *what* code does — only *why*, when the reason isn't obvious from the code itself.
- **Respect the dev container setup** (`.devcontainer/devcontainer.json`). Don't work around it (global tools outside the container, hardcoded host-specific paths). If the container itself needs to change (new port, new dependency), edit `devcontainer.json`.
- **Never put API keys, secrets, or credentials in code files.** All secrets go in `.env.local` (gitignored), read via `process.env`. Document new secret keys (not values) in `.env.example`.
- **Test changes before finishing.** Run `npm run build`, `npm run lint`, and `npm test` (if the change touches pure logic). Exercise the actual feature path in a browser for user-facing changes — passing type checks/tests is not the same as verifying the feature works.
- **Keep this file and other docs in sync** with what the app actually does.

## Architecture & Conventions

- **Every user-facing write goes through a `SECURITY DEFINER` Postgres function**, never a direct table write from the client. These run with `set search_path = ''`, so every reference inside them must be schema-qualified (`public.leagues`, `auth.uid()`, etc.). Authorization lives inside the function body (`auth.uid()` checks), not in RLS alone — RLS on these tables is read-scoping, not write-scoping.
- **Column-level grants, not blanket ones, for self-editable rows.** e.g. `profiles` grants `UPDATE (display_name, avatar_url)` only, not a blanket `UPDATE`, since RLS's "owner" policy only checks row ownership and a blanket grant would let a user set any column on their own row (including privilege flags). Follow this pattern for any self-editable column that shouldn't be fully user-writable.
- **Server actions split logic from authorization.** Non-trivial write logic lives in a plain exported function in `src/lib/*.ts` (DB-free where possible, or taking an already-authorized client); the `"use server"` action wrapping it is thin — just the "who's allowed" check plus a call into that function. This makes the logic callable from a test script directly, without a live Next.js request context.
- **Atomic draft lifecycle (prepared audit release):** draft saves, correction seeding and release/withdraw use service-only transactional RPCs with an explicit actor check. Published edits require a matching correction token and base publication timestamp; ordinary delayed autosaves cannot overwrite a published episode. Missing correction rows block publication. Settings writes use `update_scoring_categories_checked` with a revision; do not call the legacy RPC from the app. Invite secrets are excluded from table SELECT grants; only an owner RPC returns a live seven-day code.
- **Atomic results publication**: `publishEpisodeAtomically` (`src/lib/episode-publication.ts`) reads a consistent service-only `episode_publication_snapshot`, projects results/couple statuses, and computes every league's score rows through `buildWeeklyScoreRows` (`src/lib/weekly-score-rows.ts`, shared with reveal and retroactive recomputes). `commit_episode_publication` installs dances, judge scores, outcomes, couple statuses, future-cast pruning, weekly standings, custom moments, publication metadata and draft cleanup in one PostgreSQL transaction. It briefly locks the affected tables and compares the snapshot before writing; changed inputs return an error for refresh/retry, and any write failure rolls everything back. Both RPCs deny anon/authenticated execution; the action and SQL commit check super-admin access. `supabase/apply-atomic-episode-publication.sql` is applied live (RPC availability verified, types regenerated); a fresh project must apply it before deploying this code. Missing RPCs fail before any live write. No point rules changed. Autosave uses `DraftSaveQueue` edit revisions and serialized requests, drains newer edits before publish/release, and keeps failed edits dirty for retry.

Readers branch on `danceCardRule`. Score History keeps v1's wording (Kylie: the rule changes the numbers, not the copy): under v3 `Harry: Jdg 30 × 0.273`, then Survival and Bonus lines; under v2 the multiplier is that week's credit over its input. - **Lifeline and the Equalizer (Kylie, 2026-11-10, `docs/design/lifeline-recast-trades/plan.md`; `supabase/apply-lifeline.sql`, applied live 2026-11-11 and verified):** a commissioner opt-in in League Settings → Dance Card (`LifelineSettings`, default off). A manager with a dead roster slot (its couple eliminated or withdrawn, not refilled) picks one couple still dancing that they don't hold, per slot per week, on `/leagues/[id]/lifeline` (`LifelineCard`, opened from Picks; `loadLifelineWeek`, `src/lib/lifeline-week-data.ts`, shared with Picks; `saveLifelinePicks` → `set_lifeline_pick` / `clear_lifeline_pick`; locks at `lifeline_lock_at`; peers' picks are hidden until the lock; a viewer who is behind gets a catch-up state, `lifelinePicksState`, and the page shows any viewer who is behind only the catch-up card). The pick pays `max(0, 0.5 × that couple's Dance Card credit that week)` whatever the couple's outcome (Kylie, 2026-11-10: a couple that goes home still pays, its credit just has no survival step; a bye has no credit, so it pays 0), then the Dance Card weight (`buildLifelinePayouts`, `src/lib/lifeline.ts`). **`weekly_manager_scores` is unchanged**: its writers delete and reinsert rows, so Lifeline lives in `lifeline_picks` / `lifeline_payouts` / `league_point_adjustments`, and **every reader that shows or ranks totals reads the `weekly_manager_standings` view** through `loadWeeklyStandings` (`src/lib/weekly-standings.ts`: the stored row plus `lifeline_points`, `transfer_points` and a `total_points` that includes both; it falls back to the table while the view is missing). Publication settles Lifeline in the same transaction: the plan carries `lifelinePayouts` and `lifelineEqualizers`, and `apply_lifeline_settlement` checks their coverage and refuses a plan without them while a league plays. The **Equalizer** is a one-time catch-up for slot-weeks already lost (0.5 × the mean credit of the couples that danced, one that went home that week included, the same as a pick on it would pay; per dead slot-week from the Anchor Week to the week before Lifeline starts): turning Lifeline on opens a confirm sheet with every manager's amount and the standings before and after (`loadLifelinePreview`, a dry run), the commissioner confirms with or without it (`confirmLifeline` → service-only `enable_lifeline`), and it is stored as one `lifeline_equalizer` adjustment on the latest scored week, recomputed on a re-publish. Score History adds `Lifeline: {couple}` and `Lifeline Backfill` lines under Dance Card (`withLifelineLines`); Standings' Dance Card total includes them (`storedDanceCardPointsByManager`); the Couples Leaderboard does not. A league can't switch Dance Card version once it has Lifeline points (trigger).
- **Recast v2 (Mirrorball's waiver wire; `supabase/apply-recast-v2.sql`, rehearsed in `recast-v2-db.test.ts`, applied live 2026-11-11 and verified, the `pg_cron` job scheduled):** League Settings → Recast is Off or On (Waiver Wire); on always means reverse standings, with no commissioner step. On `/leagues/[id]/waivers` (`RecastPanel`) a manager keeps a ranked, private list (`saveRecastList` → `save_recast_list`, which replaces the list): each claim fills an open spot (a couple who went home, or a spot a trade emptied, shown as Open Spot) or is paired with a drop of a couple still dancing, and the drop only happens if that claim wins. `process_due_recasts` (service only, called by `pg_cron` every 15 minutes, `supabase/queries/schedule-recast-cron.sql`) decides each league once per completed week, 48 hours after the week's results are posted (Kylie, 2026-11-10, `supabase/apply-recast-after-results.sql`, applied live 2026-11-11 and verified; the last night of a multi-night week counts, and until every night is posted `recast_next_cycle.due_at` is null and the app says "48 hours after Week N results are posted"; it never runs without results); `recast_cycles` stamps the run, so it is idempotent. Managers take turns in reverse standings (`recast_order`, mirrored by `recastOrder` in `src/lib/recast.ts`: lowest season total, then the lower latest week, then the later draft pick), each awarded at most one claim a round, their highest that can still win; every award sends the turn back to the top of the order, so a manager waiting on a couple someone else is dropping takes it ahead of anyone after them (`run_recast_claims`). A winner starts scoring in the next week that hasn't aired (`recast_next_cycle` gives the due time and start week); the dropped couple shows on the wire as a pending drop and can be claimed in the same run; lists clear after each run, a manager can't reclaim a couple they dropped in that run or the next, and there is no run after the Finale. A week that came due before Recast was turned on (`leagues.recast_on_since`) never gets a run, and `save_recast_list` refuses claims for one that Trades is keeping alive. The file is safe to apply again: saved lists are renumbered only on the first apply. Missed claims are shown only to their owner (`RECAST_MISS_COPY`); awards are public, spoiler-gated, in the page's Adds and Drops log and on Home's Recent Activity. A site admin sees `RecastOverdueNotice` on Enter Results when a run is due and hasn't happened, which now only means the job is stuck (`recast_runs_overdue`). - **Trades (`supabase/apply-trades.sql`, rehearsed in `trades-db.test.ts`, applied live 2026-11-11 and verified):** its own switch in League Settings → Dance Card (`TradesSettings`, `set_trades_enabled`, default off, independent of Recast; turning it off cancels open offers and accepted trades). - **Data model facts:**
  - `roster_slots` is a timeline, not a snapshot: one row per occupancy period, current occupant is the row with `end_week is null`.
  - `people` unifies celebrities/pros/judges under one table (`role` column) so the same real person is one row across seasons/dances. `people.archived_at` soft-hides a judge (don't hard-delete one with `judge_scores` history). **Guest judges are per episode**: Schedule's episode sheet sets them (`episode_guest_judges`, written by `applyEpisodeSchedule`; a new name is created as an archived judge via `resolveGuestJudgeIds`, so it never joins the standing panel). Enter Results' score boxes are the standing panel (not archived) plus that episode's guests (`judgesForScoreInputs`). A guest's score is in the raw `total_score` fans see (a four-judge night is out of 40), but fantasy points pay on `scaled_score`, see Scoring. `episodes.guest_judge_name` is a dead leftover caption.
  - `league_id → leagues(id)` FKs cascade on delete; `manager_id`/`user_id`/`commissioner_id → profiles(id)` FKs do not.
  - **Co-manager**: a team can have a second person (duo, max 2) with full parity via `league_members.co_manager_id`. Every team-scoped table still stores the primary's `user_id` as the team identity. `resolve_acting_league_member(p_league_id)` resolves either id back to the primary; write RPCs route through it. Any client-side "is this me" comparison of `auth.uid()` against a manager/user column must check both ids (`findOwnMembership`/`isOwnMembership` in `src/lib/acting-manager.ts`) or a co-manager sees themselves as a stranger to their own team. Combined display name goes through `formatManagerName` (`src/lib/manager-display.ts`).
  - `leagues` persist across seasons; only `couples`/`episodes` (and anything keyed to them) carry a `season_id`, resolved via `active_season_id()`.
  - **Episode vs Week:** an Episode is one TV airing (`episodes.episode_number`, unique per season). A Week is a fantasy competition round (`competition_weeks.week_number`, unique per season) — `episodes.week_id` links them, and a week can span multiple episodes. Exhibition/interview nights leave `week_id` null and never appear on Results/Picks. Admin/site-ops copy uses `formatEpisodeLabel` (`S35 E02`); fan-facing copy uses the casual helpers in `src/lib/format-week.ts` (`Week N` / `Week N — {theme}`, `formatNightsLabel`). Predictions, `weekly_manager_scores`, spoiler progress, and elimination outcomes key off `week_id`; dance scores key off `episode_id`.
  - **Dance styles vs round types:** `dance_styles` is what was danced (waltz, jive, …) and carries a `category` (`ballroom`/`latin`/`show`). Round types (Team Dance, Trio Dance, Instant Dance, …) are a managed `round_types` table; `episode_round_types` is now written by `save_episode_rounds` from the plan's round names (Schedule chips, Freestyle (Team) labels), not ticked by hand.
  - **Curtain Call lock** is computed, never stored: `prediction_lock_at(league, week)` = the week's first night on the league's coast (`leagues.prediction_lock_coast`: `east` = `episodes.airs_at`, `west` = 8pm PT that day, the West feed) minus `prediction_lock_hours_before_air` (negative = after the curtain), capped at the end of that broadcast (`duration_minutes`) so picks never stay open past the elimination (`supabase/apply-west-coast-pick-lock.sql`). Submits, peer-pick visibility (RLS), Home, Picks and copy-picks all read that one RPC; `curtainCallLockAt` (`src/lib/curtain-call-lock.ts`) mirrors it only for the League Settings "Week N locks …" preview. Set in League Settings → Curtain Call (Air Time + Pick 'Em Lock hours Before/After the Curtain). The Grand Finale deadline stays on East time. The audit deadline migration preserves an established expired deadline through anchor/schedule/draft-reset edits; A commissioner can change Curtain Call timing at any time, even to reopen a week that has already locked or lock an open one immediately (`supabase/apply-drop-curtain-call-lock-guard.sql` removed the server guard); League Settings asks them to confirm either flip first (`pickLockFlip`). Genuine season rollover and intentional scoring exemptions remain supported.
  - Auto-draft (`make_auto_draft_pick`) uses the on-the-clock manager's private `draft_queues` ranking, falling back to a random eligible couple. Timeout uses `leagues.current_turn_started_at` + `pick_time_limit_seconds`; sit-out is `league_members.draft_autopilot`. `draft_picks.is_auto`/`auto_source` record how a pick was made server-side only. `leagues.draft_type` is `snake`/`linear`/`custom` (custom stores the full sequence in `leagues.custom_pick_order`). Turn-order resolution lives in `src/lib/draft.ts` (`managerIdForPick`) — don't hand-roll it elsewhere.
  - Recast/waiver couple status must go through `spoilerSafeCoupleStatus`/`resolveSpoilerCutoff`/`isSpoilerSafeActive` — never key copy or eligibility off raw `eliminated`/`withdrawn`.
  - **Grand Finale** ranks the whole season cast (eliminated couples included). Couples whose elimination is already revealed to the viewer are pinned first via `pinEliminatedFirst` (`src/lib/grand-finale-pins.ts`); pinning is UI-only, the RPC doesn't enforce it.
  - **The finale only has about 4–5 couples**, and they are not eliminated one by one: they receive final placements (1st–5th; only winner/runner-up/third are stored as statuses, 4th/5th are derived from elimination order; couples out in the same week each take the best placement in their shared range, `finalPlacementFromRange`, matching Grand Finale's best-of-range). So a 16-couple season has roughly 11–12 real eliminations across the regular weeks, which is why some weeks must be flagged `is_double_elimination_week`. Never assume one elimination per week or that every couple is eliminated; **Doubles are never known ahead of time**, only once the episode airs, so `is_double_elimination_week` is the default plan, not truth. `slotWeeks` (`src/lib/scoring.ts`) maps a Grand Finale spot to a week using the real elimination counts for weeks that have happened (through the scored week, or the viewer's cutoff on Picks) and one per later week, and treats every spot after the last regular week as the Finale (`seasonFinaleWeek`: the week marked Finale, else the last).
  - **Grand Finale late entry**: after the deadline, a commissioner (or a super admin, in any league, including one they aren't in) unlocks one manager for another manager from League Settings → Grand Finale (open that module's accordion) → Missed the lock, via `unlock_grand_finale_late` (`supabase/apply-grand-finale-late-unlock.sql`).   - **Scoring**: `scoring_settings` holds commissioner-editable point values. Defaults are strong-play season ceilings from `src/lib/strong-play-ceilings.ts` (printed by `scripts/monte-carlo-calibration/run.mjs`). A category weight is a share of that ceiling: weight 1 means Dance Card (median snake seat, skill-expected survival, season-average judges — not a perfect-30 max), Curtain Call (perfect picks), and Grand Finale (perfect bracket) each top out at the same season total. All three modules are on by default (the create dialog pre-ticks them; `create_league` only drops Grand Finale when the season has no premiere time). Grand Finale is not capped at 3/5. `create_league` seeds weight 1 for every module it turns on and does not redistribute. League Settings splits weight evenly across the modules that stay on when one is toggled (`redistributeModuleWeights` in `src/lib/scoring-neutral.ts`) and leaves point values alone. Reset to Neutral restores the strong-play point defaults plus that even split; both stop once the Season Clock lock has passed. **Judges points pay on `dance_scores.scaled_score`** (judges' average × 3, `scaledJudgesScore` in `src/lib/scoring.ts`, written beside `total_score` on every save, publish and reveal), so a guest-judge or missing-judge night stays on the three-judge basis the defaults assume; `total_score` stays the raw sum fans see, and Curtain Call's top scorer (and its within-1/within-2 bands) compares that raw total, combined across the couple's dances. **Dance Card pays a couple once per night, never once per dance**: `collapseToNights` / `nightScaledScoresByCouple` (`src/lib/scoring.ts`) turn a couple's rows for one episode into one night — all marks received over all marks possible (judges × that dance's per-judge max) × 30, plus any bonus-round points in the numerator only (`max_score = 0`), unrounded until the multiplier — so a 28/40 plus a team 36/40 is 64/80 → 24, the same as one 24/30, not 21 + 27, and a +3 dance-off on a 30/30 night is 33. ## Environment Gotchas

- **No live database credentials in this container.** Schema/RPC changes are written to a `.sql` file for the user to run via the Supabase Dashboard SQL Editor, then verified afterward with the service-role key. Never wrap SQL in a bash heredoc when handing it over — paste it as a plain `.sql` file or fenced block only.
- **Integration-test against the live project with real throwaway accounts**, not service-role bypass — most RPCs check `auth.uid()`, which a service-role call never populates. Pattern: `admin.auth.admin.createUser()` + anon client `signInWithPassword()`, always cleaned up (including the throwaway `auth.users` rows) in a `finally` block.
- **Headless browser checks**: the container has Debian's `chromium` (installed by `devcontainer.json`) driven through `playwright-core`. `scripts/qa-screenshots/seed.mjs up|down` builds and tears down a scratch league of worst-case names with throwaway accounts; `scripts/qa-screenshots/shoot.mjs <out-dir> [--at <iso>]` signs in as its viewer against the running dev server and screenshots the fan tabs at 360px and 390px (`--at` pins `Date` for curtain/live-air states). Chromium cannot emulate iOS safe-area insets, the keyboard or rubber-band scrolling, so those stay phone checks.
- **Ad-hoc verification scripts must run from the project root**, not a scratchpad directory — otherwise ESM `import` of `@supabase/supabase-js` fails to resolve `node_modules`. Also needs `NODE_OPTIONS="--experimental-websocket"` on Node 20, or the realtime client throws "native WebSocket not found" even for scripts that never touch realtime.
- **`league_members.role` only accepts `'commissioner'` / `'manager'`** — not `'member'`.
- **A stale `tsconfig.tsbuildinfo` can make `next build`'s type-check fail with an error that doesn't match current source.** If that happens and `npx tsc --noEmit` passes clean, `rm -rf .next` and retry before assuming the code is broken.
- **This repo often has more than one thing in flight** (parallel sessions, the iOS Capacitor wrapper's `project.pbxproj`). When committing, stage files by name for the specific change being made — never `git add -A` — so unrelated in-progress work doesn't get swept in.

## UI Component Patterns

- **Add new base-nova primitives via the shadcn CLI**, not by hand: `npx shadcn@latest add <name>` pulls it already adapted to this project's import paths and styling.
- **Base UI's `Select` needs an explicit `items` prop** (`Record<string, ReactNode>`) or the closed trigger renders the raw value instead of a resolved label.
- **`Button` composed with `render={<Link .../>}` needs `nativeButton={false}`** — `Button` defaults to `nativeButton={true}`, which assumes a real `<button>`; composing onto a `Link` renders an `<a>` and Base UI logs a console error in dev otherwise. Our `Button` restates `role="link"` whenever `nativeButton={false}` (Base UI would announce it as a button), so only use that for links. (Doesn't apply to `SheetTrigger`/`DialogTrigger` wrapping a `Button` — those still render a real `<button>`.)
- **A Base UI `Dialog`/`Sheet`/`Tabs` root supports multiple `Trigger`s** pointing at the same root — no need to lift state to open the same sheet/dialog from two places.
- **`Button` has a built-in touch hit area**: on coarse pointers every size reaches 44px tall (icon sizes also widen 4px a side) through an invisible `::before`, so don't use `before:` on a `Button` for visuals, and don't hand-roll per-button tap padding.
- **Error messages use `text-danger-text` with `role="alert"`**; `destructive` is for fills and borders only (as text it's 3.4:1 on the background).
- **Use the `cn` helper** (from the `cn` package, tailwind-merge-compatible) instead of raw `clsx` — a later conflicting class always wins, so it's safe to override a generated component's default classes via `className`.
- **Date/time hydration safety**: absolute date/time formatting (viewer's local timezone) must be computed client-side after mount (`useEffect`, empty deps), never during initial render — the server has no meaningful browser timezone. Relative durations (a countdown) have no such ambiguity and are safe to compute in a Server Component.
- **Module order is Curtain Call → Dance Card → Grand Finale everywhere** it's listed (Your Picks sections, Standings, Settings, create-league dialog). Defined once in `SCORING_MODULES` (`src/lib/scoring-modules.ts`) — derive any new module list from it.
- **Capitalization**: anything that names a thing (page/card/section titles, buttons, badges, field/setting labels, dropdown options, nav items) is Title Case. Full phrases and sentences (descriptions, helper text, status/empty messages) stay sentence case. Hidden `aria-label`s are left alone.
- **League at a Glance on Picks** (Dance Card, Curtain Call, Grand Finale) sits behind one shared collapsed-by-default hop, `LeagueGlanceHop` (`src/components/league-glance-hop.tsx`), that expands the peer list in place — never a sheet. Curtain Call and Grand Finale only render it after lock.
- **App frame**: the whole app is one phone-width column (`--frame-width`, 30rem, set in `globals.css`) centered on a darker `--desk` backdrop, with a shadow from 520px up; the root layout owns it, so pages don't set their own max width. The page itself still scrolls. Anything `fixed` (tab bars, the Enter Results Publish bar, bottom sheets) caps itself at `max-w-(--frame-width)` so it stays inside the column. **Fan/admin tab bars** stay `fixed` to the viewport bottom on every width. Shared chrome is `BottomNav`/`FanBottomNav` (`src/components/bottom-nav.tsx`).
- **Spacing**: use 12px main section gaps and card vertical padding/gaps, with 16px horizontal card/page gutters. PageHeader has no bottom margin; its parent supplies the separation so margins and gaps do not stack. Fan content starts 12px below sticky chrome, and Picks/Standings do not add outer top padding before that chrome. Nested settings/modules use 16px section gaps. The Home curtain has a 160px minimum and grows with wrapping text; short activity feeds grow to their content up to the 288px scroll cap. Standings manager names wrap safely and occupy at most two lines while collapsed; opening the row shows the full name. Preserve type sizes, action hit areas and bottom-nav/safe-area clearance when tightening layouts.
- **Loading skeletons**: Home, Results, Picks and Standings each have a `loading.tsx` rendering `FanPageSkeleton`, so a tab tap paints instantly. League Settings, draft, waivers, Settings, Notifications and Manage Leagues render the tab-bar-less `PageSkeleton` (same file). A `loading.tsx` covers every route below it, so pages whose folder has child routes sit in a route group instead: Home in `(fan)` (so it doesn't cover login/admin), Manage Leagues in `leagues/(manage)` (so it doesn't cover `/leagues/[id]/*`). Admin has none on purpose: editor navigation remains sensitive to pending writes. Internal links now await a save; dirty reload/close prompts and cleanup flushes best-effort. Abrupt browser termination remains a delivery limit (BACKLOG). Page loaders start independent queries together (`Promise.all`); keep new queries out of the serial chain unless they truly depend on an earlier result. Reads every fan page shares (active season, spoiler progress, weeks/episodes, the viewer's memberships, couples) go through the per-request `React.cache` loaders in `src/lib/viewer-season-data.ts`, so nested loaders reuse one read; never cache them across requests (spoiler state and RLS are per viewer). The signed-in user comes from `getAuthUser` (`src/lib/supabase/server.ts`), one Auth round trip per render shared by the layout, page and loaders.
- **App identity**: name, slug and tagline live in `src/config/app.ts`; `src/app/manifest.ts` builds the install manifest from it and `public/` holds the home-screen icons and `mark-glyph.png` (the top-bar mark), all cropped from the mirrorball art in `docs/design/logo/assets/` onto flat plum (`#401b47`, sampled from that art; `assets/icon.png` for the native iOS wrapper is still the old purple MM). Replace them under the same filenames. `usePersistedState` prefixes every `localStorage` key with the app slug.

## Settled Decisions

Deliberate omissions and naming calls. Code can't record an absence, so these come back as "improvements" otherwise — don't re-propose them.

- **Grand Finale late unlocks have no deadline** (Kylie, 2026-10-20). An open late entry can be submitted any time; the penalty is that couples already resolved when it's submitted never pay. A couple eliminated on air but not yet published still counts as unresolved, so `apply-audit-deadlines.sql` refuses a late submit while any week has aired and is unpublished (Kylie kept this pause, 2026-10-21; audit DATA-2/SEC-7/BE-9). Until that script is applied live, a late submit between the curtain and publish can still be paid for that night's elimination. The pause is not a deadline; don't add one.

- **Curtain Call's top scorer follows the show's own leaderboard** (Kylie, 2026-11-03): a couple's raw total that night across every dance, special dances and show bonus points included (`sumDanceScoresByCouple`). Don't exclude bonus points or partial-cast specials from it.

- **Show bonus points count against the night's marks, not at a fixed rate** (Kylie, 2026-11-04): a Points-mode dance's points go in the night's numerator only (`collapseToNights`), so +3 makes a 30/30 night 33 but a 60/60 night 31.5, the same share of the night they are on the show's own leaderboard. Going over 30 is fine; the category weight still applies.

- **No Special Moments card on Enter Results** (Kylie, 2026-11-04): custom events were label-only and never used (zero rows), and the automatic Perfect Score / Judges' Save badges only repeated what the Leaderboard and Finish Week already show. `supabase/apply-retire-special-leftovers.sql` drops the empty `draft_episode_custom_moments` / `episode_custom_moments` tables and `mutate_draft_moment`, and rewrites the snapshot, correction seed, Finish Week and both reveals without them.

- **Dance Card is not copyable across leagues** (drafts are per-league); only Curtain Call and Grand Finale are.
- **No light/dark toggle** — one fixed look by choice. No theme redesign is planned either. `globals.css` pins Tailwind's `dark:` variant to always apply (`@custom-variant dark`) and sets `color-scheme: dark`, so the phone's own appearance setting changes nothing.
